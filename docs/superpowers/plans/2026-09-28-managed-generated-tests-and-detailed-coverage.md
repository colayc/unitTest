# Managed Generated Tests and Detailed Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make generated C/C++ tests maintainable across regeneration and expose authoritative project/file/function/line/branch coverage, while remaining completely offline and preserving explicit review before every workspace write.

**Architecture:** Add Protocol v1.6 as an additive, paginated contract over the existing local Go service. Coverage parsers feed a durable `CoverageDetailIndex`; generated blocks are tracked by a durable `ManagedTestRegistry`; a three-way `ManagedTestReconciler` compares accepted/current/generated bytes and hands only digest-bound decisions to the existing atomic publisher. The Code-OSS extension consumes service-authoritative IDs and renders coverage, source decorations, and managed-test reviews without becoming an authority for identity, coverage, or write safety.

**Tech Stack:** Go test service and SQLite migrations; JSON Schema plus generated Go/TypeScript protocol models; TypeScript test client and Code-OSS extension; CMake; CppUTest and Unity; gcovr and llvm-cov; Node.js evidence/report tooling; GitHub Actions on Windows x64 and Linux x64.

**Spec:** `docs/superpowers/specs/2026-09-28-managed-generated-tests-and-detailed-coverage-design.md`

## Global Constraints

- Stay completely offline after reviewed bundles are prepared. Never add a cloud API, local LLM, new server process, Mock/Stub framework, CppUMock, or CMock.
- Extend the existing `apps/test-service`; the shipped product remains Code-OSS plus the built-in extension, local service, fixed tool bundles, and license files.
- Protocol v1.6 is additive. Do not change v1.0-v1.5 wire semantics or generated files. v1.0-v1.4 retain the 1 MiB line limit; v1.5 and v1.6 retain the existing 2 MiB limit. Large v1.6 data is paginated, not enabled by raising that limit.
- The Go service is authoritative for workspace generation, source/file/function/gap identity, coverage aggregation, managed-test state, review digests, and write eligibility. The extension may display results and collect explicit choices only.
- One source file maps to one generated test file under `tests/generated/`. Managed blocks are deterministic, non-nested, digest-bound, and grouped by source function. Bytes outside managed blocks must be preserved exactly.
- Never auto-overwrite an edited managed block, auto-delete an orphaned block, or publish a stale review. Marker corruption, ambiguous coverage attribution, path escape, symlink/reparse traversal, digest drift, and tool identity drift fail closed.
- A retained generated test must contain a real assertion, compile, pass in isolation, pass the existing suite, increase at least one requested coverage metric, and regress none. Reconciliation never weakens existing candidate validation.
- Every task starts with a failing test, ends with focused verification and a separate commit, and receives review before the next dependent task.
- Do not push, create/merge a PR, run hosted workflows, publish a Release, enable signing, or claim license/legal approval without the user's explicit authorization for that external action.
- `releaseReady` remains `false` until the real eight-block native matrix, coverage/mutation/abuse/performance receipts, Windows signing, and third-party legal/license approval are all closed.

## Closed Protocol v1.6 Surface

The implementation must use these method names consistently:

```text
coverage/details/project/get
coverage/details/files/list
coverage/details/functions/list
coverage/details/lines/list
managedTests/records/list
managedTests/reviews/get
managedTests/reviews/apply
```

Protocol v1.6 `testGeneration/start` replaces client-supplied symbol/file selectors with service-issued `functionId`, `fileId`, or `coverageGapId`. Existing v1.5 requests and routes remain unchanged.

All page responses carry `workspaceGeneration`, `coverageReportId`, `items`, and optional `nextCursor`. The maximum file/function/record page is 200 items; the maximum line-detail page is 1,000 items. A cursor is valid only for the exact report, workspace generation, parent ID, filter, order, and limit for which the service issued it.

## Review Focus

Reviewers must treat these cases as release-blocking:

1. A rerun duplicates cases, changes deterministic bytes, or loses hand-written bytes outside managed blocks.
2. An edited managed block reaches the publisher without a current three-way review and explicit digest-bound resolution.
3. Project, file, and function totals disagree, or inline/template/macro expansion is double-counted.
4. Ambiguous attribution is represented as an exact percentage instead of `incomplete`.
5. A source/tool/report/workspace drift leaves a review current or writes any bytes.
6. Restart/cancellation leaves partial writes, silently accepts a candidate, or advances registry state without verification.
7. The v1.6 UI silently falls back to v1.5 data and exposes a non-authoritative generate/write action.
