# Windows 单次生产目标解析的工具摘要复用设计

日期：2026 年 10 月 11 日。

状态：用户已同意保存“单次目标解析内复用工具摘要”的设计范围，暂不实施；下列具体契约等待书面设计确认。代码基线为 ea1c9d18，原有 V2 工作继续暂停。

## 目标与证据边界

将已有 Windows 工具摘要保护从单次覆盖率索引的内部，扩大到一次 productionRuntimeContextReader 所支撑的 ResolveProductionContext 调用。目标是减少外围发现对同一工具文件反复进行的全量哈希，而不是缓存工作区发现、目标列表、报告、覆盖率图、源码或权限校验结果。

已完成的单次组件诊断中，三个普通发现合计 43.4315835 秒；两个共享现有保护作用域的发现合计 4.150587 秒。后者实际完整哈希 12 个工具文件、复用 26 次，成功释放全部保护句柄。覆盖率持久图和源码绑定合计 3.2875 毫秒。

诊断使用隔离构建根描述符，五次发现与原基线的 generation 不相同；这不是完整目标解析重放，也不是原 native 失败的修复证明。设计不承诺精确加速倍数、消除全部耗时或一定在 300 秒内完成生成。

## 与已有设计的关系

本设计是 [Windows protected tool digest reuse](2026-10-09-windows-protected-tool-digest-reuse-design.md) 的有限范围补充，不替换已实现的工具身份、摘要、回退和并发保护机制。

旧设计中每次 ReadCurrentCoverageIndex 都拥有独立作用域。补充后，只有当前生产目标解析内部的该次索引读取可借用父作用域；独立索引查询依然新建、关闭自己的作用域。不得将本次补充解释为跨查询、跨生成阶段或服务生命周期缓存。

## 方案比较

| 方案 | 收益与代价 | 本设计结论 |
| --- | --- | --- |
| 单次目标解析拥有作用域，内部索引借用 | 覆盖外围三次发现；需明确父子所有权和作用域绑定 | 采用，符合已同意的范围 |
| 保留索引内部作用域不变 | 无新增所有权边界，但外围三次完整哈希仍存在 | 保留作独立索引路径，不解决本次外围成本 |
| 在生成阶段之间或整个任务期间共享 | 可进一步减少重复工作，但延长保护时间、扩大缓存边界 | 不采用，超出本次范围 |

不使用开始时一次解析替代后续解析，不提前读取生成流水线缓存来跳过目标重建。RunStage 仍先做现有目标解析，然后处理生成结果缓存。

## 作用域与组件

这里的“单次解析”严格指一次 runtimeProductionResolverAuthority.ResolveProductionContext 方法调用，从通过入口参数校验后到返回前。不是一次完整测试生成任务，也不是一个浏览器或扩展会话。

每次解析都新建作用域，即使输入 context 曾用于另一次解析，也不能继承上一解析的摘要。并发解析互不借用；每个解析独立受 128 个工具文件上限约束。不存在进程全局缓存、TTL、持久缓存或跨阶段引用。

采用三项窄职责组件：

- 解析拥有者：仅在当前方法内新建作用域、绑定选择字段、检查作用域失败并负责关闭。
- 索引借用视图：为当前内部索引调用提供同一作用域的 Err 检查及借用结束通知，不拥有工具句柄，不得关闭父作用域。
- toolhash 只读绑定校验：确认给定 context 绑定的是指定 Scope，且调用 context、Scope、原父 context 仍可用。不能仅检查 Scope.Err，因为现有 Err 并不单独表示正常关闭后的 closed 状态。

内部 context 标记由 runtime 创建，绑定当前 Scope 及已校验的 projectID、workspaceGeneration、reportID。它不属于公开协议，不来自 IPC、客户端字段或环境变量，不进入持久数据和返回结果。

只读绑定校验不得新增任意提取或关闭其他 context 作用域的通用接口，也不改变现有 toolhash.Begin 的“每次调用新建”语义。

## 拥有与借用契约

| 调用路径 | 作用域行为 | 工具保护句柄的关闭者 |
| --- | --- | --- |
| Windows 生产目标解析 | 新建并拥有一个作用域 | 当前解析拥有者 |
| 当前解析内部的匹配索引读取 | 借用同一个作用域，不再新建第二个 | 仍是解析拥有者 |
| 没有解析标记的独立索引查询 | 保留现有新建作用域逻辑 | 当前索引读取 |
| Linux 和其他非 Windows 路径 | 保留原校验逻辑，不创建可复用工具保护 | 无新增拥有者 |

索引借用前必须核对三项选择字段与当前解析标记一致，并验证实际 toolhash context 绑定及活动状态。字段不匹配、绑定不匹配、已关闭或已失败的父作用域均拒绝借用，不能创建新作用域掩盖失效。

没有私有解析标记时，即使 context 带有其他 toolhash 状态，也不能任意借用；独立索引仍按原规则新建作用域。解析入口也不借用输入中的旧标记，而为当前调用创建新拥有者和新绑定。

索引借用视图的 Close 只结束该视图，不调用父 Scope.Close；其结束时的失败检查必须能阻止索引成功返回。重复结束是幂等的。父作用域在索引结束后继续有效，供解析结束前的最后一次发现使用。

当前父子调用是同步调用；父方法等待内部索引返回后才能正常结束。不得通过增加后台借用任务、跨调用引用计数或无界等待扩展生命周期。既有取消后发现 goroutine 的收尾仍由现有 Scope 关闭及生产探测清理机制承担。

## 数据流与保留校验

1. 按现有入口校验 reader、context、projectID、generation 和 reportID。拒绝的参数不新建作用域；取消和原绝对截止时间不能被当成可选保护失败。
2. Windows 新建当前解析拥有的保护作用域，立即注册所有返回路径的关闭动作，绑定私有解析标记。继承原 context 和截止时间，不重设请求时间预算。
3. 进行第一次完整 InspectWorkspace，核对 generation、项目、报告、运行结果及覆盖率配置、基础构建配置等既有绑定。
4. 原样执行 ListTargets，保留其内部发现、CMake File API、配置指纹、当前工具链、声明和选定 SDK 相关校验。
5. 原样进入 ReadCurrentCoverageIndex，读报告和运行后验证借用条件，再执行其前后两次完整发现、持久图完整校验和全部索引源码绑定。
6. 原样计算报告摘要，进行解析结束前的最后一次完整发现，并核对 generation 和项目、构建配置、覆盖率配置的相等性。
7. 检查 context 及作用域是否已失败，关闭拥有的作用域；仅在原校验成功且关闭成功时返回原有值类型结果。

成功路径仍有五次完整工作区发现。新作用域仅改变这些发现中符合既有资格的工具摘要如何被复用，不删除探测，不缓存其输出，也不改变既有校验的位置或次数。

报告、运行、持久图、工作区配置、预设、声明、源码、维护用例、工具束清单、权限及单独认证的选定 SDK 库不进入该摘要复用范围。工具消费者的父目录、发布边界、普通文件、大小、路径和身份校验照常执行。

## 工具证据与资源边界

沿用现有工具资格规则。首次完整计算 SHA 256 前持有 Windows 禁止写入和删除共享的独立保护句柄；消费者保留各自的读句柄与 Close 所有权，不共享 seek 偏移。

每次复用仍验证实际路径、消费者句柄、保护句柄和文件对象身份。路径、时间戳、大小或摘要相同不能单独证明身份。不得扩大别名、重解析点或命名空间支持，不将不同硬链接名称自动合并成缓存项。

整个单次解析共用一个最多 128 个工具文件的容量池，内部索引不得额外再拥有 128 个。每工具最多 512 MiB 的复用资格、已有更严格的消费者限制及现有拼写数量限制均保留。独立并发解析的容量分别计算，不新增服务级共享配额。

保护时段扩大到这次解析的入口至退出，仅影响符合资格的工具，不保护或锁定用户源码与可维护测试文件。仍沿用产品控制的工具发布假设，不声称可对抗内核、特权修改或既有可写映射。

## 回退与失败处理

不符合资格、可选容量耗尽、或首次无法建立文件保护且路径仍稳定的情况，继续调用原完整哈希和校验路径，不返回未经验证的摘要。这些可选回退条件不能扩大或缩小输入原有的接受边界；真实绑定失效仍必须拒绝。

已经绑定的工具身份或路径变化、保护失效、摘要读取错误、作用域错误、错误的内部绑定，以及取消和超时，均不能降级为无害未命中。即使发现器将工具消费者错误转为尽力而为的诊断，父解析也必须检查真实作用域失败并拒绝成功结果。

父子路径返回错误时都不能携带成功解析结果或成功索引。原参数、过期、存储、取消及超时错误优先保留，不新增公开错误协议。索引选择字段不匹配使用原参数拒绝语义；错误或失效的作用域绑定使用原存储不可用语义，并保留既有取消和超时处理顺序。

拥有者在成功、前置发现失败、目标列表失败、内部索引失败、最后发现失败、异常或取消的所有退出路径关闭 Scope。若原操作已经失败，不用清理错误替换其主错误；若原操作成功而关闭失败，清空结果并通过现有错误类别拒绝成功。

借用者只能释放借用视图；不能提前关闭父作用域，也不能在父关闭后继续复用。已有 Scope 的入场关闭、流式取消、首次摘要发布、重复 Close 和短临界区规则不改为跨外部探测持锁或无界等待。

## 定点验证要求

未来实施必须先有行为 RED，再以同一明确选择器获得 GREEN；编译失败、缺失方法或测试未运行不能代替行为 RED。本设计不执行这些测试，也不生成实施控制器。

必要的验证集中于：

- 通过真实解析权威入口与真实内部索引借用路径，证明五个发现位置都执行、符合资格的同一小型工具文件在该解析内只完整哈希一次。
- 内部索引结束后父作用域仍活动，最后一次发现继续复用；父解析结束后写入和删除限制解除，旧证据不可再用。
- 同一输入 context 的下一次解析新建作用域并重新哈希；独立索引查询仍保留原有首次哈希和查询结束即释放行为。
- 正常借用、无标记、选择字段错误、context 绑定错误、已关闭、已失败及取消的父作用域；错误借用不能重新开作用域掩盖问题。
- 第一和最后工作区 generation 或配置变化、报告和运行绑定变化、持久图失效及源码变化仍按原路径拒绝；不能仅断言最终发现次数。
- 普通工具消费者的既有全量回退、容量和大小限制不变；父和内部索引合计不超过 128 个保护文件。
- 每个失败位置、粘性作用域失败被发现器吞掉、关闭错误及取消后并发收尾，都返回空结果并释放拥有的句柄；借用结束不双重关闭父句柄。
- 同一解析内并发 CMake 和工具链发现共享保护；两个并发解析分别持有自己的作用域，不互相污染或关闭。
- Linux 与未标记消费者没有新增复用权威；现有 deadline 不重设，生成缓存之前的目标重建仍执行。

优先复用既有 runtime 固定元数据夹具和小型真实临时工具文件验证身份及写删保护；不以模拟摘要代替真实哈希和保护证据。定点测试不要求实际运行生产工具发现、Clang 分析或完整 native；原测试证据不整批重跑。

成功标准是安全边界和重复哈希次数得到定点证明，而不是某个固定的耗时阈值。随后若需要测量真实目标解析或重新验收 native，必须分别取得有界授权并保留独立证据。
